# Защита темы 4

## Объяснение за минуту

Программа удаляет заданный цвет фона из видео и подставляет другой цвет или картинку. Каждый кадр представляется в YUV: Y описывает яркость, U и V — цветность. FFmpeg chromakey сравнивает цветность с выбранным пользователем цветом и строит альфа-маску. Допуск задаёт область удаляемых оттенков, мягкость — плавность перехода. Затем кадр накладывается на новый фон по формуле C = alpha*foreground + (1-alpha)*background. Результат кодируется в MP4; аудио сохраняется с учётом исходного смещения относительно видео.

Это описание алгоритма. Код создавался с помощью ИИ; студент должен понимать его и самостоятельно выполнить тренировочные изменения.

## Что объяснять в исходниках

- `upload`: сохранение под случайным идентификатором, ffprobe, лимиты, выбор видеодорожки, средний fps, смещение звука, нормализация пикселей и поворота.
- `color` и `number`: серверная проверка параметров. Фильтры FFmpeg собираются только из проверенных значений; subprocess запускается без shell.
- `command`: единый набор фильтров для предпросмотра и полной записи. `chromakey` создаёт прозрачность, `despill` уменьшает зелёные/синие отражения, `overlay` накладывает объект, `scale`/`crop` готовят фон.
- `start` и `render`: одно фоновое задание; HTTP-запрос возвращает идентификатор, браузер опрашивает статус, ошибки не выдаются за готовое видео.
- `result`: выдача MP4 и частичных HTTP Range ответов для перемотки; скачать файл можно с Content-Disposition attachment.
- `static/app.js`: загрузки, синхронизация HEX и палитры, пипетка через координаты canvas с учётом масштабирования и пустых полей, запрос обработки, показ результата и скачивание.

## Вопросы по теории

**Почему это компьютерная графика?** Здесь используются цветовые модели, сегментация по цвету, альфа-композитинг, геометрическое масштабирование, дискретные кадры и кодирование изображения.

**Почему объект иногда исчезает?** Если его цветность похожа на фон, хромакей не может отличить их по смыслу. Это не нейросеть; зелёная одежда на зелёном фоне также будет удалена.

**Зачем мягкость?** Резкая бинарная маска даёт ступенчатый край. Промежуточная альфа сглаживает переход; слишком большая мягкость делает объект полупрозрачным.

**Почему YUV?** Цветность отделена от яркости, поэтому умеренные изменения освещения фона меньше влияют на выбор. Но тени и отражения всё равно требуют настройки. Ахроматические цвета различаются в основном яркостью, поэтому этот метод лучше подходит цветному экрану.

**Как подгоняется фон-картинка?** Пропорционально увеличивается до покрытия кадра; излишки обрезаются по центру. Объект не растягивается под размеры новой картинки.

**Почему не сохранить видео без перекодирования?** Изменились пиксели каждого кадра. H.264 выбран для совместимости браузеров; MP4/AAC сохраняют привычный формат, но с потерями кодирования.

**Что на другом датасете?** Алгоритм не использует имя файла или эталонную маску курса. Цвет и параметры выбирает пользователь. Пригодны видео с однотонным цветным фоном в пределах лимитов.

## Тренировка

1. Изменить длину предпросмотра с 5 до 3 секунд в `command`, обновить подписи в HTML/JS и тест длительности.
2. Поменять цвет нового фона по умолчанию согласованно в HTML и сервере.
3. Объяснить и изменить CRF 20: меньше число — больше качество и размер файла.
4. Отключить despill и сравнить край на зелёном экране.
5. Добавить новый тест: синий фон, красный объект, белая подложка; проверить реальные пиксели результата.
